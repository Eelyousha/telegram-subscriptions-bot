# Блок-схема процесса миграции

## 🔄 Процесс миграции (Автоматический скрипт)

```
┌─────────────────────────────────────────┐
│   Запуск: ./scripts/migrate.sh         │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Проверка Docker Compose              │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Проверка статуса контейнеров         │
│    (api, bot, db должны быть Up)        │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Проверка текущей версии              │
│    alembic current -> 001?              │
└───────────────┬─────────────────────────┘
                │
                ├─► Если 002 → ✅ Уже применено, выход
                │
                ▼
┌─────────────────────────────────────────┐
│  📦 Создание автоматического бэкапа     │
│     backup_YYYYMMDD_HHMMSS.sql          │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ⚠️  Запрос подтверждения пользователя  │
│     "Продолжить? (yes/no):"             │
└───────────────┬─────────────────────────┘
                │
                ├─► no → Отмена, выход
                │
                ▼ yes
┌─────────────────────────────────────────┐
│  🔄 Применение миграции                 │
│     alembic upgrade head                │
│     001 → 002                           │
└───────────────┬─────────────────────────┘
                │
                ├─► Ошибка → ❌ Вывод инструкций по откату
                │
                ▼ Успех
┌─────────────────────────────────────────┐
│  ✓ Проверка применения                  │
│    alembic current -> 002?              │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ♻️  Перезапуск сервисов                │
│     docker compose restart api bot      │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Проверка типа колонки                │
│    \d users -> telegram_id: bigint      │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Health check API                     │
│    curl /health -> {"status":"healthy"} │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  🎉 МИГРАЦИЯ УСПЕШНО ЗАВЕРШЕНА          │
│                                         │
│  • Версия: 002                          │
│  • Бэкап: backup_*.sql                  │
│  • Тип: bigint (int64)                  │
└─────────────────────────────────────────┘
```

## 🔙 Процесс отката (Автоматический скрипт)

```
┌─────────────────────────────────────────┐
│   Запуск: ./scripts/rollback.sh        │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Проверка текущей версии              │
│    alembic current -> 002?              │
└───────────────┬─────────────────────────┘
                │
                ├─► Если 001 → ℹ️  Откат не нужен, выход
                │
                ▼
┌─────────────────────────────────────────┐
│  ⚠️  Проверка MAX(telegram_id)          │
│     SELECT MAX(telegram_id) FROM users  │
└───────────────┬─────────────────────────┘
                │
                ├─► > 2,147,483,647 → ❌ ОТКАТ НЕВОЗМОЖЕН
                │                         Данные не влезут в int32
                │
                ▼ <= 2,147,483,647
┌─────────────────────────────────────────┐
│  ⚠️  СТРОГОЕ подтверждение              │
│     "Введите 'ROLLBACK':"               │
└───────────────┬─────────────────────────┘
                │
                ├─► Не ROLLBACK → Отмена
                │
                ▼ ROLLBACK
┌─────────────────────────────────────────┐
│  📦 Создание бэкапа перед откатом       │
│     backup_before_rollback_*.sql        │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ⏸️  Остановка сервисов                 │
│     docker compose stop api bot         │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  🔄 Откат миграции                      │
│     alembic downgrade -1                │
│     002 → 001                           │
└───────────────┬─────────────────────────┘
                │
                ├─► Ошибка → Восстановление из бэкапа
                │
                ▼ Успех
┌─────────────────────────────────────────┐
│  ✓ Проверка отката                      │
│    alembic current -> 001?              │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ▶️  Запуск сервисов                    │
│     docker compose start api bot        │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✓ Проверка типа колонки                │
│    \d users -> telegram_id: integer     │
└───────────────┬─────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────┐
│  ✅ ОТКАТ ЗАВЕРШЕН                       │
│                                         │
│  ⚠️  ВНИМАНИЕ:                           │
│  telegram_id ограничен 2,147,483,647    │
│  Новые пользователи могут вызвать ошибку│
└─────────────────────────────────────────┘
```

## 📊 Структура данных: До и После

### До миграции (001)

```sql
users table:
┌─────────────┬──────────┬──────────┐
│ telegram_id │ username │ ...      │
├─────────────┼──────────┼──────────┤
│ INTEGER     │ VARCHAR  │ ...      │
│ (int32)     │          │          │
│ Max:        │          │          │
│ 2,147,483,647         │          │
└─────────────┴──────────┴──────────┘
                  ❌ ОГРАНИЧЕНО

subscriptions table:
┌────┬─────────────┬──────┬─────┐
│ id │ telegram_id │ name │ ... │
├────┼─────────────┼──────┼─────┤
│ PK │ FK INTEGER  │ ...  │ ... │
│    │ (int32) ────┼──────┼─────┤
└────┴─────────────┴──────┴─────┘
                  ❌ ОГРАНИЧЕНО
```

### После миграции (002)

```sql
users table:
┌─────────────┬──────────┬──────────┐
│ telegram_id │ username │ ...      │
├─────────────┼──────────┼──────────┤
│ BIGINTEGER  │ VARCHAR  │ ...      │
│ (int64)     │          │          │
│ Max:        │          │          │
│ 9,223,372,036,854,775,807       │
└─────────────┴──────────┴──────────┘
                  ✅ ДОСТАТОЧНО

subscriptions table:
┌────┬─────────────┬──────┬─────┐
│ id │ telegram_id │ name │ ... │
├────┼─────────────┼──────┼─────┤
│ PK │ FK BIGINT   │ ...  │ ... │
│    │ (int64) ────┼──────┼─────┤
└────┴─────────────┴──────┴─────┘
                  ✅ ДОСТАТОЧНО
```
